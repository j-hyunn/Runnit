## 2. 페이스 그래프 — **손그림 유지 (fl_chart 미채택)**

pubspec 주석이 fl_chart를 "페이스/고도/심박 **추이**"용으로 적어 두었지만, HI-02의
페이스 그래프는 추이가 아니라 **랩 3~10개짜리 범주형 막대**다. 그 차이가 결정을
갈랐다.

1. **fl_chart의 주 기여분이 이 그래프에선 대부분 무효화된다.** 페이스(s/km)는
   작을수록 빠르므로 축을 뒤집어야 하고, 눈금 라벨도 `4'52"` 형태여야 한다. 두
   가지를 하려면 `getTitlesWidget`으로 축·격자 로직을 거의 다 덮어쓰게 된다.
   남는 건 툴팁 정도인데, 값은 바로 위 랩 테이블에 이미 전부 있다.
2. **같은 탭 안의 시각 언어 일관성.** `MonthlyBarChart`(활동 탭 월별 그래프)가
   이미 손그림이다. 여기만 fl_chart를 쓰면 한 화면 안에서 막대 굵기·모서리·라벨
   톤이 미묘하게 어긋난다.
3. **번들 비용.** 이 화면 하나 때문에 차트 엔진을 로드할 이유가 없다.

fl_chart는 P1의 **고도·심박 연속 추이** 차트에서 실제로 값을 한다. 그때 도입한다.
(pubspec에서 제거하지는 않았다 — P1 예정이므로.)

### "빠른 구간 = 강조"를 읽히게 한 장치
- 막대 높이를 **뒤집었다**: 빠를수록 길다(러닝 앱 관례). 정규화 범위 0.30~1.00.
- 최속 랩만 진한 초록 `#00C84B`, 나머지는 옅은 초록 `#9BE3B6`, 자투리는 회색.
- 축 라벨 대신 상단 범례에 `가장 빠른 구간 4'20"` / `가장 느린 5'30"`를 직접 찍는다.
- 랩 테이블도 최속 행에 초록 텍스트 **+ 옅은 초록 배경**을 함께 깐다 —
  색상만으로 구분하면 색각 이상 사용자에게 단서가 사라지기 때문이다.
- 각 막대에 `Semantics` 라벨(구간·페이스)을 붙여 스크린리더로도 읽힌다.

### 스케일 엣지 케이스
- 전 구간 페이스 차이가 1초 미만이면 정규화 분모가 0에 수렴해 막대가 노이즈로
  요동친다 → 균일 높이(0.65)로 그리고 범례를 "전 구간 페이스가 고르게 …"로 바꾼다.
- 자투리 구간은 스케일 계산에서 **제외**하고(페이스가 튄다) 실제 값으로 클램프해
  옅게만 그린다.
- 마라톤(42랩)처럼 막대가 많으면 폭을 줄이는 대신 **가로 스크롤**로 전환한다
  (최소 12pt). 3pt짜리 막대는 높이 차이를 읽을 수 없다.
- 완전 구간이 2개 미만이면 그래프를 아예 그리지 않는다(`PaceChart.canRender`).
  호출부가 섹션 제목을 그리기 전에 이걸 묻게 해서 "제목만 있고 본문이 빈 섹션"을
  막았다.

## 3. 랩 계산 검증 (`lap_splits.dart`)

서버 정본은 마이그레이션 41의 `_run_time_at_distance` / `_run_km_split_seconds`다.
1차 초안을 그 SQL과 한 줄씩 대조해 다음을 수정했다.

### 3.1 서버 분기와 맞춘 것
- 목표 거리 0 → 첫 샘플 시각
- 두 샘플의 누적거리 차가 0(일시정지) → 보간하지 않고 뒤쪽 샘플 시각
- 어떤 샘플도 목표 거리에 도달 못 함 → **그 랩을 방출하지 않음**
- 경계 통과 시각 = 누적거리 비율 선형 보간

### 3.2 고친 버그
| 문제 | 수정 |
|---|---|
| **누적거리가 있어도 좌표가 없으면 버렸다.** 서버는 `cumulative_distance_meters`만 보는데, 초안의 `_usablePoints`는 lat/lng 필수라 좌표 없는 워치 임포트 기록에서 랩이 통째로 사라졌다 | 거리 원천을 `_DistanceBasis`로 분리. 1순위 = 누적거리(서버와 동일 입력), 2순위 = 좌표 Haversine 폴백 |
| **랩 경계마다 고도 상승분 유실.** `(from, to]` 구간만 보니 구간 첫 오르막의 기준점이 없었다(테스트로 검출: 기대 20m → 실제 10m) | 고도처럼 **차분**으로 내는 지표는 구간 직전 샘플 하나를 기준점으로 붙인다(`includeAnchor`). 심박 평균은 경계 샘플이 앞 구간 것이므로 그대로 엄격 범위 |
| **누적거리 비단조 시 보간 루프 오작동** | 러닝 맥스로 비감소 강제(`_monotonic`) |
| **자투리 판정이 `total % 1000 != 0`** — 부동소수 나머지에 의존해 Haversine 경로에서 불안정 | `floor()`로 완전 랩 수를 세고 잔여 거리를 별도 계산 |
| **50m 미만 꼬리도 자투리 랩이 됐다** — 종료 직전 좌표 흔들림이 "페이스 23'00\" 구간"으로 표에 남았다 | `minPartialLapMeters = 50` |
| **duration 0일 때 페이스 `0'00"`** 표시 | 페이스 0 반환 + 표시는 `RunFormat.pace`(가드 있음)로 통일. 초안은 `Formatters.pace`(가드 없음)를 썼다 |
| 경계 시각을 초로 반올림하기 전에 차분해, 표의 시간과 그 시간으로 계산한 페이스가 어긋날 수 있었다 | 경계 시각을 먼저 반올림 → 랩 시간은 정수 차분 → 페이스는 그 값에서 파생. 표시값과 계산값이 항상 일치 |

### 3.3 서버와 **의도적으로 다른** 지점 (문서화됨)
1. **자투리 구간을 내보낸다.** 서버는 완주된 정수 km만 방출한다
   (`pace_variance_lte`가 자투리를 섞으면 왜곡되므로). 화면에서 마지막 600m를
   감추면 "기록 누락"으로 읽히므로 `isPartial: true`로 함께 내보내되, 최속 판정·
   그래프 스케일에서는 제외한다.
2. **좌표 Haversine 폴백.** 서버 입력에는 없는 경로다. 구버전 로컬 기록처럼
   누적거리가 비어 있을 때 감추는 것보다 근삿값이라도 보여주는 편이 낫다는 판단.
   이 경로에서는 서버 값과 미세하게 어긋날 수 있음을 소스 주석에 명시했다.

> **재확인 요망(qa-integration-tester / backend-engineer):** 위 2번 폴백 때문에
> 상세 화면의 랩 페이스가 서버 뱃지 판정 근거와 소수점 단위로 다를 수 있다.
> 화면 값은 표시용이고 판정은 서버가 재계산한다는 ARCHITECTURE §7.2 전제가
> 유지되는지만 확인해 주면 된다.

## 4. 상태 처리 (모두 구현·테스트됨)

| 상태 | 화면 |
|---|---|
| 로딩 | `CircularProgressIndicator` |
| 조회 실패 | "기록을 불러오지 못했어요" + **다시 시도**(provider invalidate) |
| 기록 없음(null) | "기록을 찾을 수 없어요" — 재시도 버튼 **없음**(다시 눌러도 없다) |
| 실내 러닝 | 지도 자리에 기존 `RunMapUnavailable` 재사용 + "실내 러닝은 경로를 기록하지 않아요." |
| 야외인데 경로 유실 | 같은 위젯 + "이 기록에는 저장된 경로가 없어요." |
| 랩 없음 (100m 미만) | "1km 구간을 나누기에는 너무 짧은 기록이에요." |
| 랩 없음 (경로 자체 없음) | "경로 데이터가 없어 구간·페이스 그래프를 만들 수 없어요." |
| 완전 랩 1개뿐 | 랩 테이블만, 그래프 섹션은 제목까지 통째로 생략 |
| `isFlagged == true` | 주황 배너 "티어·랭킹에 반영되지 않았어요" |
| `isFlagged == null` | **배너 없음.** null은 "아직 검증 전"이지 이상치가 아니다 — 업로드 직후 지나가는 상태에 누명을 씌우지 않는다 |
| `flagReason` | **노출 안 함.** 모델 주석대로 내부 코드에 가까운 문자열 |

## 5. 그 밖의 수정

- **provider `autoDispose` 전환.** `runDetailProvider`는 1시간 러닝 = 약 3,600
  `RunSample`을 물고 있다. autoDispose가 아니면 기록을 훑을수록 메모리가 단조
  증가한다.
- **경로 좌표를 provider로 승격**(`runRoutePointsProvider`). 초안은 `hasRoute`와
  `build`가 각각 폴리라인을 디코딩해 리빌드마다 중복 작업을 했다.
- **OSM 출처 표기 추가.** OSM 타일 이용 정책상 필수인데 빠져 있었다.
  - ⚠️ **후속:** 트래킹 화면 `RunMapView`에도 같은 표기가 없다. 이번 범위 밖이라
    손대지 않았으니 별도로 처리 필요.
- **`maxZoom: 17` 상한.** 제자리 러닝처럼 경계 폭이 0에 가까우면 `CameraFit`이
  최대 줌까지 파고들어 타일이 비어 보인다.
- **요약 통계 반응형화.** 초안의 `FractionallySizedBox(1/3)` in `Wrap`은 320pt
  폰에서 값이 줄바꿈된다. `LayoutBuilder`로 폭에 맞춰 2~4열을 정한다.
- **랩 테이블 4번째 열.** 초안이 계산만 하고 버리던 `elevationGainMeters`를
  살렸다. 심박(웨어러블)이 있으면 심박, 없고 고도가 있으면 고도, 둘 다 없으면
  열 자체를 뺀다. 폰 폭에서 5열은 셀이 줄바꿈된다.

## 6. 범위 밖 (미구현)

- **HI-07 (기록 삭제 / 제목·메모 수정).** 리포지토리에 수정 경로가 없고, 삭제는
  티어·랭킹 재계산까지 걸린다. 상세 화면 코드 주석에 명시해 두었다.
- **HI-08/HI-10 공유 버튼.** 상세 화면 공유 진입점은 PRD에 명시가 없어 넣지
  않았다(현재 공유는 요약 화면 트리거). 필요하면 gamification-designer와 확인.
