## 2. 설계 판단

### 2.1 반환 타입은 `RunRecord`가 아니라 `RunMeta`

편집 응답으로 행 전체를 되받으면 제목 한 줄 고치자고 1시간 러닝의 3,600 샘플을 다시 내려받는다. `select('id,title,note,updated_at')`만 요청하고 `RunMeta`(title·note·updatedAt)로 받는다 — `_confirmationColumns`가 업로드 응답에서 쓰는 것과 같은 방침이다.

**서버가 보낸 값과 다른 값을 돌려줄 수 있다**(`btrim` → 절단 → 빈 문자열은 `null`). 그래서 반환값은 인자를 되돌려주는 것이 아니라 서버 확정값이고, 시트가 그 값을 로컬에 반영한 뒤 화면이 그것을 그린다. 위젯 테스트가 "보낸 값(공백 포함)과 화면에 그려진 값(trim)"이 다름을 검증한다.

### 2.2 업로드 upsert 재사용이 아니라 부분 `update`

`_push()`의 전체 행 upsert로도 편집은 되지만(서버가 나머지를 되돌린다) 샘플을 통째로 재전송한다. 순수한 낭비라 `update({'title','note'}).eq('id', …)`를 따로 둔다.

### 2.3 아직 서버에 없는 기록(오프라인 저장분) — 분기 근거는 로컬 `sync_status`

*(2026-08-31 QA C-1·C-2 반영으로 판정 근거를 서버 응답에서 로컬 상태로 옮겼다. §6 참조)*

`sync_status`가 `synced`가 아닌 행은 서버에 존재한 적이 없다(`save()`가 완료 기록만 올리고 실패하면 `pending`/`failed`로 남는다). 그러므로 **네트워크를 아예 타지 않고** `RunMeta.normalized()`로 로컬에서 확정한다 — 서버 가드와 같은 규칙(trim → 절단 → 빈 문자열 `null`)을 쓰고, 나중에 `syncPending()`이 갱신된 `summaryJson`을 그대로 실어 올린다.

`synced` 행은 반드시 서버를 친다. `maybeSingle()`이 `null`(0행)이면 그것은 "미업로드"가 아니라 **이상 상태**(서버에 행이 없거나 RLS 매칭 실패)이므로 `Failure.network`로 표면화한다. 여기서 로컬만 고치면 `syncPending()`이 재전송하지 않아 영구 divergence가 생기는데 사용자에겐 성공으로 보인다.

절단은 UTF-16 코드 유닛이 아니라 **룬 단위**다. Postgres `left()`가 코드포인트 단위로 자르므로, BMP 밖 이모지가 섞이면 코드 유닛 기준 절단이 서버와 다른 길이를 만든다.

### 2.4 `sync_status`는 건드리지 않는다

편집이 성공했다고 `synced`로 올리면 본문 업로드가 아직 안 끝난 `pending` 기록이 동기화 큐에서 빠진다. 반대로 `pending`으로 내리면 이미 올라간 기록의 3,600 샘플을 통째로 다시 올린다. 그래서 `_applyMeta()`는 `summaryJson`과 `updated_at_local`만 쓴다.

### 2.5 실패는 스낵바가 아니라 시트 안 인라인 (요청 대비 변경점)

과제는 "네트워크 실패 시 스낵바"였으나 두 가지 이유로 인라인으로 바꿨다.

1. 시트가 모달이라 뒤 `Scaffold`의 스낵바가 배리어에 가린다. 보이게 하려면 시트를 닫아야 한다.
2. 시트를 닫으면 **사용자가 방금 쓴 메모가 함께 사라진다.** 지하 주차장에서 러닝을 끝낸 직후가 정확히 이 실패 국면이다.

그래서 실패는 시트를 열어 둔 채 빨간 한 줄로 알리고 재시도하게 하고, **성공 스낵바("기록을 수정했어요")만** 시트가 닫힌 뒤 호출부가 띄운다.

### 2.6 삭제 UI 없음 — 화면에도 명시

PRD v1.6 §8.1. 서버에 삭제 정책 자체가 없으므로(마이그레이션 51-3) 버튼을 두면 로컬 행만 지워지고 다음 원격 조회에서 기록이 되살아난다. 시트 부제에 "제목과 메모만 고칠 수 있어요. 거리·시간 기록은 바꿀 수 없어요."를 두어 **왜** 안 되는지가 아니라 **무엇이 되는지**를 먼저 말한다. 위젯 테스트가 '삭제' 문구 부재를 회귀 방지로 잡는다.

### 2.7 `delete()`에서 서버 호출 제거

두 호출부(`TrackingController.discard()`, 미완결 세션 배너 "버리기")는 모두 `recording`/`paused` 체크포인트를 지운다 — `save()`가 완료 기록만 올리므로 애초에 서버에 없던 행이다. 마이그레이션 51-3으로 삭제 정책까지 사라졌으니 남겨 두면 폐기할 때마다 0행짜리 왕복 요청만 나간다. **완료 기록 삭제 호출부는 없었다**(제거할 것 없음).

## 5. QA CONFIRMED 수정 내역 (2026-08-31, `_workspace/20260831_183000_qa_hi07.md`)

### C-1 · C-2 — 편집 분기를 서버 응답 → 로컬 `sync_status`로 이전

`local_run_repository.dart`의 `updateMeta()`가 이제 로컬 행을 먼저 읽고 분기한다.

| 로컬 상태 | 동작 |
|---|---|
| `local`/`pending`/`failed` (미업로드) | 네트워크 호출 없음. `RunMeta.normalized()`로 로컬 확정 후 반환. `sync_status`는 그대로라 `syncPending()`이 이 값을 실어 올린다 |
| `synced` (또는 로컬 행 없음 = 다른 기기 기록) | 서버 `update` 호출. **0행이면 `Failure.network`** — 로컬을 바꾸지 않는다 |

이전 코드는 오프라인이면 `guardSupabase`가 던져 `_applyMeta`에 닿지도 못했다 — 지하 주차장에서 러닝을 끝내고(업로드 실패, `pending`) 메모를 쓰려는, 오프라인 우선 아키텍처가 정확히 겨냥한 국면에서 편집이 막혔다. 그리고 `confirmed == null`을 무조건 "미업로드"로 읽어, `synced` 행에 0행이 오면 로컬만 갈라진 채 성공으로 보였다.

회귀 테스트: `test/history/update_meta_test.dart` — 도달 불가 원격 주소를 두고 **"네트워크를 탔는가"를 예외 발생 여부로 관찰**한다(`find_by_id_samples_cache_test.dart`와 같은 수법). ① `pending`은 예외 없이 로컬 반영 + `sync_status` 유지, ② `synced`는 예외 + 로컬 불변.

### C-3 — 길이 계수 단위를 룬(코드포인트)으로 통일

Flutter 기본 `maxLength`(= `LengthLimitingTextInputFormatter`)는 **grapheme cluster**로 세는데 서버 `char_length`/`left`와 `normalizeRunMetaField()`는 **코드포인트**로 센다. `👨‍👩‍👧‍👦`(1 grapheme / 7 코드포인트)가 섞이면 UI가 서버보다 관대해져 이모지가 반토막 난 채 조용히 저장된다.

- `maxLengthEnforcement: none`으로 기본 포매터를 끄고, `RuneLimitingTextInputFormatter`(신규, 시트 파일)로 교체.
- 카운터도 `ValueListenableBuilder` + `runes.length`로 바꿔 같은 단위로 표시(`56/60`).
- **절단 지점은 룬 예산 안의 grapheme 경계**다. 룬 경계에서 그냥 자르면 서버와 똑같이 반토막 이모지가 나온다 — 상한을 넘기지 않는 선에서 한 글자 덜 받고 온전한 문자만 남긴다. 서버보다 관대해지지 않으므로 계약을 깨지 않는다.

회귀 테스트: `run_detail_page_test.dart` — 👨‍👩‍👧‍👦 10개(70 코드포인트) 입력 → 8개(56)만 남고 카운터가 `56/60`.

### C-4 (수정 없음, 확인만)

제목을 그리는 곳이 상세 화면뿐이라 "긴 제목의 목록/공유 카드 렌더 검증"은 **깨질 위젯이 없다.** 아래 §6 대기 항목에서 내렸다. 목록 타일/공유 카드 제목 노출은 별도 과제.

## 6. 남은 이슈

1. **마이그레이션 51이 아직 원격에 적용되지 않았다.** 적용 전에는 서버 정규화(trim·절단·빈 문자열→`NULL`)와 컬럼 화이트리스트가 없다. 클라이언트는 `maxLength`로 초과 입력을 먼저 막지만, **앞뒤 공백 trim은 51 적용 전까지 서버에서 일어나지 않는다**(로컬 전용 편집 경로만 클라이언트가 정규화한다).
2. **이미 업로드된(`synced`) 기록의 오프라인 편집 큐는 없다.** 서버 UPDATE가 실패하면 시트가 실패를 알리고 아무것도 저장하지 않는다(로컬만 바꿔 두면 서버 값과 갈라진다). 지원하려면 `sync_status`와 별개의 "메타 편집 pending" 축이 필요하다 — MVP 범위 밖. **미업로드 기록의 오프라인 편집은 C-1 수정으로 해결됐다.**
3. **제목이 상세 화면 밖에는 표시되지 않는다**(QA C-4). 60자 상한의 근거였던 "목록 카드/공유 카드의 한 줄 제목" 표면이 아직 없다. 상한은 그대로 두되, 목록 타일/공유 카드 제목 노출을 별도 과제로 올릴 것.
4. 서버 마이그레이션 51 적용 후 재검증 대기 — 편집이 티어·랭킹·XP를 흔들지 않는지, ZWJ 이모지 절단 위치가 클라이언트 예상과 맞는지.
