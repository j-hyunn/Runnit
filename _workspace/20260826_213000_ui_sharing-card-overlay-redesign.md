# 공유 카드 재설계 — 9:16 불투명 카드 → 16:9 투명 오버레이 스티커

**날짜:** 2026-08-26 · **담당:** flutter-ui-designer · **범위:** PRD HI-08 / HI-10 (P0)
**요청 원문:** "공유카드는 배경이 없고 16:9 페이지에 각 기록과 경로를 보여줄 수 있도록 만들고 싶어.
그래서 사람들이 알아서 본인들의 사진에 오버레이로 적용할 수 있게끔 만들거야. 폰트는 업로드한 폰트를 사용해줘."

---

## 1. 무엇이 바뀌었나

| | 이전 | 현재 |
|---|---|---|
| 비율 | 9:16 (세로 풀스크린) | **16:9 (가로 밴드)** |
| 출력 해상도 | 1080×1920 | **1920×1080** |
| 배경 | `Color(0xFF101216)` 불투명 | **없음 — 알파 0** |
| 모서리 | `ClipRRect(AppTokens.rLg)` | 없음 (클립 제거) |
| 서체 | Pretendard Variable | **Orbitron**(수치·라벨·문구) + Pretendard 폴백(한글) |
| 사용 방식 | 이미지 자체를 스토리에 게시 | 사용자 사진/영상 위에 **오버레이 스티커** |
| 브랜드 마크 | 워드마크 + 알약 배지 2벌 | `RUNNIT` 워드마크 1벌 |
| 성취 카드의 경로 | 전면 16% 워터마크 | 삭제 (기록 카드에서만 그림) |

## 2. 판단이 필요했던 지점과 근거

### 2.1 출력 해상도 = 1920×1080

스토리 캔버스는 1080 폭이다. 밴드를 캔버스 폭에 꽉 맞추면 1080×608이면 충분하지만,
사람들은 스티커를 **손가락으로 확대해 캔버스보다 크게** 쓴다. 1920이면 그 경우에도
업스케일이 일어나지 않는다. 게다가 카드 면적의 대부분이 투명이라 PNG 용량은
이전(불투명 1080×1920)보다 **오히려 작다** — 실측 캡처에서 기록 카드 약 190KB,
메달이 들어간 티어/뱃지 카드 약 400KB(2.4× 배율 기준 샘플).

1080×608 같은 "딱 맞는" 값을 쓰지 않은 이유: 여유가 없어 확대 시 흐려지고,
16:9 표준 값이 아니라서 나중에 규격을 설명하기 번거롭다.

### 2.2 투명 배경 위 가독성 — 색이 아니라 halo로 푼다

바탕이 눈밭 사진일지 야간 사진일지 알 수 없으므로 **색 대비에만 의존하는 요소를
카드에서 전부 없앴다.** 두 가지 장치로 해결했다.

- `shareCardTextShadows(size)` — 모든 텍스트에 이중 어두운 그림자를 단다:
  좁고 진한 것(`#000` α90%, blur 0.30×글자크기)이 윤곽을 분리하고,
  넓고 옅은 것(α55%, blur 0.85×, 아래로 0.06× 오프셋)이 글자 주변 바탕을 눌러 준다.
  halo 반경이 폰트 크기에 비례하므로 큰 글자에서 테두리만 도드라지지 않는다.
- `ShareRoutePainter(haloColor:)` — 경로 폴리라인 아래에 **2.1배 굵은 어두운 획**을
  블러(`MaskFilter.blur`)와 함께 먼저 깐다. 이게 없으면 밝은 아스팔트 사진 위에서
  골드 경로선이 그대로 녹아 사라진다.

**반투명 패널을 깔지 않은 이유:** 패널을 깔면 결국 "반투명 판때기"가 되어 오버레이의
의도(사진이 그대로 보인다)가 절반쯤 무너진다. Orbitron이 획이 굵고 기하학적인
디스플레이 서체라 halo만으로 충분히 버틴다.

`shareCardTextStyle()` 헬퍼를 통과하지 않고 `TextStyle`을 직접 쓰면 halo가 빠진다 —
그래서 카드 안 **모든** 텍스트가 이 함수를 통과하도록 강제했다.

### 2.3 경로를 어디에 두는가

- **기록 카드(RunRecap)**: 왼쪽 정사각 칸의 **주인공**. `haloColor` 포함, 시작=속 빈 원 /
  끝=채운 원으로 루프 여부가 그림만으로 읽힌다. 경로가 없으면(실내 러닝) 활동 아이콘
  — 빈 사각형을 남기지 않는다.
- **성취 카드(티어/뱃지/PB)**: **경로를 그리지 않는다.** 이전 디자인의 전면 16% 워터마크는
  불투명 카드 위에서만 성립하던 처리다. 임의의 사진 위에서는 밝은 사진이면 안 보이고
  어두운 사진이면 낙서로 보인다. 경로는 주인공일 때만 그린다.

### 2.4 둥근 모서리 제거

사용자 사진 위에 앉는 스티커에 라운드 클립이 남으면 "여기 판때기가 하나 붙어 있다"는
프레임 신호가 된다. 글자와 선만 남겼다. 미리보기 화면의 체커보드에만 라운드를 남겨
카드 영역을 알려 준다(캡처 경계 밖).

### 2.5 Orbitron + 한글 폴백

Orbitron에는 **한글 글리프가 없다.** `fontFamilyFallback: ['Pretendard Variable']`을
명시하지 않으면 한글만 기기 기본 글꼴로 튀어나와 카드가 두 얼굴이 된다.
가변 폰트라 굵기는 `fontWeight`가 축으로 매핑된다(w500~w900 사용).

## 3. 레이아웃 — 공통 3층

모든 치수는 **카드 높이(`s`)** 대비 비율이다. 가로 밴드에서 빡빡한 축이 세로이기 때문이다
(이전 세로 카드는 폭 기준이었다).

```
 ┌──────────────────────────────────────────────────────────────────┐
 │ RUNNIT ──────────────────────────────  지현   Lv.12 · 골드        │  머리띠
 │                                                                  │
 │  ┌────────┐   HEADLINE (s*0.115, w800, 최대 2줄)                  │  본문
 │  │  ART   │   subhead (s*0.052, 최대 2줄)                         │
 │  └────────┘                                                      │
 │ ──────────────────────────────────────(그라데이션 헤어라인)─────  │
 │  25:00 │ 4'59"/km │ 320                         2026.08.27       │  바닥
 │  시간    페이스      칼로리                                        │
 └──────────────────────────────────────────────────────────────────┘
```

- 패딩: 좌우 `s*0.075`, 상하 `s*0.085`
- 머리띠 가운데의 강조색 선이 브랜드와 러너를 잇는다 — 밴드가 "한 줄짜리 계기판"으로
  읽히게 하고, 사진 위에서 스티커의 폭을 알려 준다.
- 아트는 **정사각**(`AspectRatio(1)`)이라 4종 모두 문구 열의 시작선이 같다.
- 헤드라인/부제는 `Flexible`로 감쌌다 — 둘 다 2줄이 되어도 RenderFlex 오버플로 줄무늬가
  PNG에 구워지지 않는다(구워지면 그대로 인스타로 나간다).

### 카드 종류별 배치

| 카드 | 아트(왼쪽 정사각) | 헤드라인 | 부제 | 수치 타일 | 강조색 |
|------|------|------|------|-----------|--------|
| 티어 승급 | 티어 엠블럼 SVG + 다크 스크림 | "골드 달성" | 티어 문구 | 시즌 / 시즌 누적 / 티어 내 상위 % | 티어 색 |
| 뱃지 획득 | 뱃지 메달 SVG + 다크 스크림 | 뱃지 이름 | 뱃지 설명 | **없음**(왼쪽 칸 통째 생략, 날짜만) | 뱃지 등급 색 |
| PB 갱신 | PB 메달 SVG + 다크 스크림 | "5km 개인 최고 기록" | 기록 시간 | 종목 / 기록 / 이 러닝 | 골드 |
| 러닝 기록 | **경로 폴리라인**(halo) | "5.01km 완주" | 요약 문구 | 시간 / 페이스 / 칼로리 | 러너의 현재 티어 색 |

`ShareCardEmblem`에 `scrim` 파라미터를 추가했다(기본 false). 카드에서만 true —
메달 뒤에 어두운 원을 깔아 밝은 사진 위에서도 실루엣이 산다. 앱 안 축하 연출
(`achievement_celebration.dart`)은 이미 어두운 다이얼로그 위라 기본값 그대로다.

**데이터 규칙은 유지했다.** 순위는 절대 등수가 아니라 `topPercent`(PRD §5.4.1),
`seasonDistanceMeters`/`certifiedSeconds`/`paceLabel`이 null이면 그 칸을 통째로 뺀다
(클라이언트가 값을 지어내지 않는다).

## 4. 미리보기 화면

- 폭 제약 `maxWidth: 360` → **`560`**, 세로는 비율이 정한다.
- 카드 뒤에 **체커보드**(`_TransparencyChecker`)를 깔았다. 배경이 없다는 걸 말로만
  설명하면 사용자는 "왜 카드가 반투명해 보이지?"로 읽는다. 이미지 편집기의 투명 표시와
  같은 관습이라 설명이 필요 없다. **캡처 경계 밖**이라 PNG에 찍히지 않는다.
- 하단 안내 문구: "인스타그램 스토리 규격(9:16)으로 저장돼요"
  → **"배경이 없는 16:9 스티커로 저장돼요. 스토리에 올린 사진 위에 얹어 보세요."**

## 5. 캡처 계약 — 유지된 것 / 새로 추가된 것

유지: 카드가 `ShareCardSurface`로 화면에 실제로 올라감(`Offstage` 금지) ·
같은 `GlobalKey`를 surface와 `captureCard`에 전달 · 캡처 중 버튼 잠금 ·
SVG 프리캐시 후 잠금 해제 · `MediaQuery.withNoTextScaling` · 카드 안에서
`MediaQuery`/다크모드를 읽지 않음.

**새 계약: 카드 위젯 트리에 불투명 배경을 넣지 않는다.**
`ui.ImageByteFormat.png`가 알파를 보존하므로 이것이 투명 PNG의 유일한 조건이다.
`ColoredBox`/`DecoratedBox`/`Container(color:)`가 하나라도 들어가면 스티커가 아니라
사진을 덮는 판때기가 된다.

## 6. 검증

- `flutter pub get` — Orbitron 자산 반영 확인. `pubspec.yaml`에 `family: Orbitron`으로
  이미 등록돼 있었다(`assets/fonts/Orbitron-VariableFont_wght.ttf`).
- `flutter analyze` — **0건**
- `flutter test` — **140건 전체 통과**(기존 139 + 신규 1)
- **알파 채널 회귀 테스트 신규 추가** (`share_card_body_test.dart`):
  카드를 실제로 `toImage()`로 구워 좌상단 모서리 픽셀의 알파가 0인지 검사한다.
  누군가 배경을 다시 칠하면 코드 리뷰가 아니라 테스트가 잡는다.
  (⚠️ `toImage`/`toByteData`는 `tester.runAsync()` 안에서 await해야 한다 —
  밖에서 부르면 테스트가 영원히 멈춘다. 실제로 한 번 걸렸다.)
- **실제 PNG 시각 검증**: 4종을 1920×1080으로 구워 중간 밝기 회색 위에 합성해 확인했다.
  레이아웃·halo·경로·엠블럼 스크림 모두 의도대로 동작. (테스트 환경 폰트는 Ahem이라
  Orbitron 자체의 자형은 실기기 확인 필요.)
- 기존 테스트 갱신 1건: 브랜드 마크가 알약 배지 → 워드마크 하나로 통합되어
  `find.text('Runnit')` → `find.text('RUNNIT')`.

## 8. 후속 (P1)

- **실기기에서 Orbitron 자형 확인.** 테스트 환경은 Ahem이라 자형 검증이 불가능했다.
  특히 숫자 폭(`4'59"/km` 같은 페이스 표기)과 한글 폴백 경계의 베이스라인 정렬.
- **여러 규격 제공 여부.** 지금은 16:9 하나다. 세로 사진에 얹을 때를 위한
  정사각/세로 밴드 변형을 원하면 `shareCardAspectRatio`를 파라미터화해야 한다
  (현재는 상수 하나로 렌더러·surface·미리보기가 동기화돼 있다).
- **TRD §14 #21 잔존**: `badgeAssetPath`(정본)와 `tierEmblemAssetPath`(share_card_body)의
  이원화는 이번 라운드에서도 그대로다.
