## 1. 화면 · 라우트

| 화면 | 파일 | 라우트 | 브랜치 | 게스트 |
|---|---|---|---|---|

게스트 차단은 코드를 추가하지 않았다 — `RouteAccess.guestAllowedPrefixes`가

`Routes.editProfile` / `Routes.userProfile` + `Routes.userProfileOf(id)` 상수를
`app_router.dart`에 추가했고, 라우터 doc 표에도 두 줄을 넣었다.

### 브랜치 배치 판단 (⚠️ QA 확인 요망)

`/users/:userId`를 **홈 브랜치**에 매달았다. 진입점이 홈 랭킹 미리보기와 거기서
`MaterialPageRoute`로 push되는 `FullRankingPage` 둘뿐이기 때문이다. `/seasons`와
같은 함정을 그대로 물려받는다 — **다른 탭에서 이 경로로 `push`하면 화면 위에
뜨지 않고 보이지 않는 홈 브랜치에 쌓인다.** 라우트 상수 doc에 경고를 달아 뒀다.
랭킹 외의 진입점(뱃지 상세, 알림 딥링크 등)이 생기면 그때 `MaterialPageRoute`로
`UserProfilePage`를 직접 띄우거나 배치를 다시 판단해야 한다.

### 진입점 배선

- 마이페이지 `_ProfileCard`의 설정 아이콘: "준비 중" 스낵바 → `context.push(Routes.editProfile)`.
- `home_page.dart` 랭킹 미리보기 / `full_ranking_page.dart` 전체 랭킹의 각 행:
  `RunnerListTile(onTap: ...)` → `/users/{entry.userId}`.
  **게스트에게는 `onTap`을 주지 않는다** — 랭킹 자체는 게스트에게 공개된 화면인데
  행을 누르면 로그인 화면으로 튕기는 건 나쁜 흐름이다. `onTap`이 null이면 잉크
  리플도 붙지 않아 "눌러도 되는지" 오해가 생기지 않는다.

## 2. AC-02 프로필 편집

편집 항목 4개: **표시이름 · 사진 · 체중(kg) · 주간 목표(km)**.
`username`은 자물쇠 아이콘과 함께 회색 읽기 전용 행으로 노출한다 — 화면에 아예
없으면 "왜 못 바꾸지"가 아니라 "어디서 바꾸지"가 되어 더 헷갈린다.

`heightCm` / `birthDate` / `gender`는 이 화면이 손대지 않지만, `updateProfile`에는
`profile.copyWith(...)` 결과가 통째로 실려 가므로 **기존 값이 지워지지 않는다**
(테스트로 못 박음).

### 검증 (서버 CHECK와 같은 범위)

| 입력 | 범위 | 빈 값 |
|---|---|---|
| 체중 | 20~400 kg | null 저장(미입력 허용) |
| 주간 목표 | **0 초과** 500 이하 (마이그레이션 53) | null 저장(= 미설정) |
| 표시이름 | 최대 20자, trim | **null 저장** — `''`를 넣으면 `AppUser.label`의 username 폴백 조건(`== null`)이 깨져 라벨이 빈칸이 된다 |

`0`은 "목표 없음"이 아니라 CHECK 위반이다. 목표를 지우려면 빈 값으로 둔다 —
이 구분은 테스트에 남겼다. 입력 포매터로 `^\d*\.?\d*`만 허용해 `,`·두 번째 `.`가
"숫자를 입력해 주세요"로 되돌아오는 상황 자체를 막았다.

### 아바타 업로드 (backend §3 계약 준수)

`lib/features/profile/data/avatar_service.dart` **신규**. 두 계약으로 나눴다:

- `AvatarPicker` / `ImagePickerAvatarPicker` — `image_picker`.
  `maxWidth == maxHeight == 512`, `imageQuality: 85`로 **네이티브 단에서**
  리사이즈·재인코딩한다.
- `AvatarStorage` / `SupabaseAvatarStorage` — 경로 규약
  `avatars/{uid}/{millisSinceEpoch}.{ext}`, `getPublicUrl` 반환.
- `AvatarPolicy` — 버킷명 / 2 MiB / jpeg·png·webp / 공개 URL ↔ 오브젝트 경로 변환.

**화면이 `image_picker`와 `SupabaseClient`를 직접 부르지 않는 이유는 하나다**:
그러면 이 화면을 위젯 테스트로 돌릴 수 없다(플랫폼 채널 + 네트워크). provider로
갈라 두어 테스트가 가짜 구현으로 갈아끼운다.

저장 순서 — 되돌리기까지 포함:

1. 새 사진 업로드 (프로필 갱신보다 **먼저** — 반대면 URL 없는 프로필이 잠깐 저장된다)
2. `updateProfile`
3. **성공 후에야** 이전 아바타 파일 삭제 (반대면 저장 실패 시 옛 사진까지 잃는다)
4. `updateProfile`이 실패하면 **1에서 올린 파일을 지운다** — 아무도 가리키지 않는
   고아 파일이 남지 않게

같은 경로 덮어쓰기는 하지 않는다(CDN 캐시). 이전 파일 삭제 실패는 사용자 흐름을
막지 않는다 — 프로필은 이미 갱신됐고, 여기서 예외를 올리면 "저장은 됐는데 에러가
뜨는" 상태가 된다.

외부 아바타 URL(카카오 CDN 등)은 `AvatarPolicy.objectPathOf`가 null을 내므로
삭제 대상에서 자동으로 빠진다.

### 상태 처리

로딩(스피너) / 프로필 없음·조회 실패(재시도 버튼) / 저장 중(버튼 스피너 + 입력
비활성) / 저장 실패(`Failure` 종류별 문구를 에러 배너로) / 성공(스낵바 + pop).
컨트롤러 시딩은 **프로필이 처음 도착한 한 번만** 한다 — 매 빌드마다 하면 입력
도중 provider가 갱신될 때 타이핑이 되돌려진다.

## 3. AC-03 타인 프로필

카드 3장: **신원 카드**(아바타 + 표시이름 + `@username` + 누적 3분할 + 역대 최고
티어) · **시즌 카드**(시즌 거리 + 현재 티어 + 진행률 바 + 다음 티어까지) ·
**획득 뱃지 카드**(그리드).

- 누적 3분할은 마이페이지 `_ProfileCard`와 같은 시각 언어지만 항목이 다르다 —
  거기는 티어/러닝/레벨이고, 여기는 시즌 카드가 티어를 따로 크게 보여주므로 그
  자리를 **누적 거리**로 바꿨다(AC-03 수용 기준의 "누적 거리/횟수/레벨").
- 진행률 바는 홈 시즌 카드와 같은 규격(네온 그린 `#00F35A`, 11px).
- 역대 최고 티어는 `bestTierOfProvider`. 끝난 시즌이 없으면 "없음"이 아니라
  **"아직 없어요"** — 0이 아니라 아직 만들어지지 않았다는 뜻이라 문구로 구분한다.
- 이메일 자리에 **아이디(핸들)**를 둔다. 이메일은 타인에게 절대 노출하지 않는다.

### 노출 금지 — 렌더링 계층이 유일한 방어선

`profiles`는 전 컬럼 공개 SELECT라 `weightKg` / `heightCm` / `birthDate` /
`weeklyGoalKm`가 **모델에 실려서 온다**. 서버가 막아주지 않으므로 화면이 그리지
않는 것 말고는 방어가 없다. 이 부재를 **테스트로 못 박았다** — 노출 금지 필드에
화면 어디에도 우연히 나타나지 않을 값(68.5 / 177 / 42 / 1993)을 넣고
`findsNothing`을 건다. 이 화면에 필드를 추가할 때 그 목록을 다시 볼 것.

개별 러닝 목록도 없다. provider 자체를 만들지 않았다(architect §3.2) — 만들면
RLS가 빈 목록을 돌려주고 화면에 "기록 없음"이라는 **거짓말**이 뜬다.

### realtime 미부착

`user_badges`는 realtime publication에 있고, 마이그레이션 55의 공개 SELECT 정책
때문에 타인의 뱃지 발급 이벤트도 구독자에게 도달한다. `userBadgesByIdProvider`의
1회성 `FutureProvider`를 그대로 소비하며, 이 화면에 스트림을 붙이지 않았다.
클래스 doc에 금지 사유를 남겼다.

### 본인 id로 들어온 경우

`context.go(Routes.profile)`로 마이 탭에 보낸다(post-frame 콜백, 래치로 1회만).
편집 진입점과 미획득 뱃지·진행률이 있는 쪽이 본인에게 더 유용하다.

## 6. 패키지 · 네이티브 설정

- `pubspec.yaml`에 **`image_picker: ^1.1.2`** 추가. `image_cropper`는 채택하지
  않았다 — iOS/Android 양쪽 네이티브 설정이 추가로 필요한데, 아바타는 어차피
  원형 클리핑돼 표시되고 `maxWidth == maxHeight`로 장변 512px에 맞추면 육안상
  차이가 없다. 별도 이미지 처리 패키지(`image` 등)도 불필요하다(피커가 한다).
- `ios/Runner/Info.plist`에 **`NSPhotoLibraryUsageDescription`** 추가.
  `NSPhotoLibraryAddUsageDescription`(저장 안 함)과 `NSCameraUsageDescription`
  (촬영 경로 미제공)은 넣지 않았다 — HealthKit과 같은 "불필요한 권한은 요청하지
  않는다" 원칙. **촬영 경로를 추가하려면 그때 함께 넣을 것.**
- Android는 추가 매니페스트 설정이 필요 없다.
