## 1. 카드 아트 (`presentation/widgets/share_card_body.dart`)

`ShareCardSurface`의 `child`만 갈아 끼웠다. 캡처 계약 4가지는 그대로다 — 카드는 화면에 실제로 올라가 있고, 같은 `GlobalKey`를 쓰고, 캡처 중 버튼을 잠그고, 카드 안에서 `MediaQuery`·다크모드를 읽지 않는다(모든 치수는 `LayoutBuilder`가 준 카드 폭 `w`의 비율).

### 공통 3단 구조

세로 9:16은 **브랜드 → 성취 → 러너**로 읽힌다. 위/아래는 4종이 공유하고 가운데만 갈라진다.

| 영역 | 내용 |
|---|---|
| 상단 | `RUNNIT` 워드마크(강조색) + 날짜 |
| 중앙 | 엠블럼/경로 + headline + subhead + 수치 타일 0~3개 |
| 하단 | 이니셜 원 + 이름 + `Lv.N · 티어` + **브랜드 마크**(무료 광고 1회가 목적이라 어떤 카드에서도 빠지지 않는다) |

### 카드별

| 카드 | 엠블럼 | 수치 타일 |
|---|---|---|
| 티어 승급 | `assets/badges/tier/{tier}.svg` | 시즌 · 시즌 누적 km · **상위 N%**(`rank` 아님 — PRD §5.4.1) |
| 뱃지 획득 | `badge_assets.dart` 경로 | 없음(이름 + 설명이 본문) |
| PB 갱신 | PB 메달 | 종목 · **기록(있을 때만)** · 이 러닝 거리(있을 때만) |
| 기록(신규) | 없음 — **경로 그림이 주인공** | 시간 · 페이스(있을 때만) · 칼로리(있을 때만) |

**빈 값 처리를 레이아웃의 기본값으로 삼았다.** 타일은 리스트로 만들고 null이면 넣지 않으며, 타일이 0개면 행 자체를 그리지 않는다 — 시간 없는 PB 카드에 빈 구분선만 남는 상황을 만들지 않는다. 실내 러닝(경로 없음)은 빈 사각형 대신 활동 아이콘을 놓는다.

### 경로 페인터 (`ShareRoutePainter`)

위경도를 상자에 맞추되 **경도를 `cos(위도)`로 보정**한다. 보정 없이 그리면 서울 위도에서 코스가 가로로 20% 늘어나 사용자가 아는 자기 코스와 다른 모양이 된다. 시작점은 속 빈 원, 끝점은 채운 원 — 루프인지 편도인지가 그림만으로 읽힌다. 직선 코스(트랙 왕복)에서 한 축의 폭이 0이 되는 NaN 케이스를 막아 뒀다.

성취 카드에서 경로는 **배경 워터마크**(opacity 0.16)다. 주인공은 메달이고 경로는 "어디를 뛰어서 얻었는지"를 덧붙인다.

### SVG 미로드 사고 방지 (아키텍처 문서 §8의 남은 위험)

`captureCard`는 프레임 하나만 기다리는데 `SvgPicture`는 비동기 로드다 → **메달 자리가 빈 카드가 인스타로 나갈 수 있다.** 시트가 열릴 때 `precacheShareCardArt()`로 자산을 데우고, **끝날 때까지 공유 버튼을 잠근다.** 앱 밖으로 나간 이미지는 회수할 수 없으므로 여기서 막는 편이 맞다.

### 자리표시자 삭제

`DefaultShareCardBody`는 지웠다. 남겨 두면 카드 디자인이 두 벌이 되고 어느 쪽이 실제로 공유되는지 코드를 읽어야 알 수 있게 된다 — 뱃지 아트 경로가 두 벌이던 것과 정확히 같은 문제다.

### 2.1 요약 화면의 게이트 분기

`AchievementGate`를 그대로 썼다.

| 게이트 | 화면 |
|---|---|
| `confirmed` | "기록이 확인됐어요…" + 도착한 성취 축하 + 공유 버튼 |
| `pending` | "아직 서버에 올리는 중이에요…" — **공유 버튼 없음** |
| `flagged` | **블록 자체를 그리지 않는다.** 회수 애니메이션도 사유 안내도 없다(TRD §11) |

**기존 문구 교체**: `tracking_page.dart`의 "포인트와 뱃지는 서버 확인 후 기록 화면에 반영돼요."를 게이트별 문구로 바꿨다. 뱃지는 이제 이 화면에서 바로 축하하므로 "기록 화면에 반영"이 사실이 아니고, **포인트는 MVP 범위 밖**(Phase 4)이라 문구에서 뺐다.

⚠️ **큐에 뜬 성취는 게이트와 별개로 이미 서버 확정이다.** `evaluate_badges()`는 `is_flagged=false` 기록만 근거로 판정하므로, 이번 러닝이 아직 `pending`이어도(예: 며칠 전 오프라인 러닝이 방금 동기화됨) 큐에 온 뱃지 자체는 공유 가능하다. 게이트가 지배하는 것은 "이번 러닝"에 대한 문구다.

### 2.2 러닝 자체의 공유 버튼은 게이트에 걸지 않았다 (판단 근거)

기록 카드는 **서버가 확정한 성취를 주장하지 않는다** — 방금 사용자가 기록한 자기 러닝의 거리·시간·경로일 뿐이다. PRD §8.4가 막는 것은 클라이언트 판정을 "확정 성취"로 내보내는 행위이고, 이 카드에는 뱃지·PB·티어 문구가 하나도 없다. 다만 **서버가 플래그한 기록은 공유 대상에서 뺀다.**

(게이트를 그대로 걸었다면 `isFlagged`가 채워지기 전까지 버튼이 영원히 안 뜬다 — 이 판단이 뒤집혀야 한다면 `RunShareButton` 한 곳만 고치면 된다.)

### 2.3 한 번에 하나 + 이중 축하 방지

- 요약 화면은 큐 맨 앞 1건만 인라인으로 축하하고, "확인"을 누르면 seen 처리되어 다음 건이 같은 자리에 나타난다(`외 N개 더 있어요` 표시). 다이얼로그를 쌓지 않는다.
- 요약 화면이 살아 있는 동안 전역 호스트는 `achievementCelebrationSuppressors`(전역 `ValueNotifier<int>` 카운터)로 억제된다. **Riverpod provider가 아닌 이유**: 값을 바꾸는 시점이 `initState`/`dispose`라 빌드 페이즈 안일 수 있고, 그때 provider를 수정하면 Riverpod가 막는다(`AppShell.measuredHeight`와 같은 패턴). bool이 아니라 카운터인 것은 화면 전환 중 두 화면이 겹칠 때 나중에 사라지는 쪽이 남아 있는 쪽의 억제를 꺼 버리기 때문이다.

### 2.4 무한 루프를 막은 지점 (놓치기 쉬운 곳)

`markAchievementsSeen`은 네트워크 실패 시 **조용히 넘어간다**(축하 화면이 오류로 안 닫히는 쪽이 더 나쁘다는 기존 판단). 그러면 같은 행이 큐에 남아 스트림이 다시 밀어 준다 →
- 전역 호스트: 다이얼로그가 무한 반복
- 요약 화면: "확인"을 눌러도 카드가 그대로 남아 **버튼이 고장 난 것처럼 보임**

그래서 양쪽 모두 **이번 실행에서 이미 보여준 id를 로컬 Set에 기억**한다. 앱을 다시 켜면 한 번 더 축하하지만, 그건 의도된 폴백이다(한 번 더 보는 쪽이 조용히 사라지는 쪽보다 낫다).

## 3. 마이그레이션 이슈 (TRD §14 #19) — 해소

`isAchievementBacklog()` (`sharing/domain/achievement_backlog.dart`, 순수 함수 + 테스트 5건):

| 신호 | 임계 | 왜 |
|---|---|---|
| 개수 | > 5 | 한 러닝이 현실적으로 터뜨리는 뱃지의 상한. 넘으면 "이번 러닝의 성과"가 아니라 밀린 것 |
| 획득 시각 간격 | > 24h | 서버는 업로드와 같은 트랜잭션에서 발급하므로 한 러닝의 뱃지는 `earnedAt`이 사실상 동일하다. 하루 이상 벌어지면 서로 다른 날의 성취다 |

둘 중 하나라도 걸리면 "그동안 받은 뱃지 N개" 한 장으로 접고 **일괄** `markBadgesSeen`. 요약 화면과 전역 호스트 양쪽에 같은 판정이 걸려 있다.

**로컬 "이미 처리함" 플래그(SharedPreferences)는 두지 않았다.** 접고 나면 서버 행이 `is_seen=true`가 되어 큐에서 영구히 빠지므로 그 상태는 **이미 서버가 들고 있다.** 같은 사실을 두 곳에 적으면 재설치·기기 변경에서 어긋나 사용자가 축하를 통째로 잃거나 두 번 본다.

## 5. 이음매 — 다른 에이전트에게

### gps-tracking-engineer
`_push()`의 `.select().single()` 반영 감사하다. 그 값을 화면까지 잇는 마지막 한 칸을 **`storedRunProvider`**(`tracking/presentation/tracking_ui_providers.dart`)로 채웠다 — `myRunsProvider`(drift `watch()`)에서 해당 id를 골라내므로 업로드가 끝나 `summaryJson`이 갱신되면 요약 화면이 자동으로 `pending → confirmed`로 승격된다. 새 단건 스트림 API는 만들지 않았다.

⚠️ 그 provider는 목록 스트림 기반이라 **`samples`가 비어 있다.** 게이트 판정값(`syncStatus`/`isFlagged`)만 읽고, 공유 카드의 경로는 손에 쥔 원본 레코드에서 뽑는다.

### mobile-architect
- `ShareCardKind`/`ShareCardData`에 **`runRecap`을 추가**했다(§1). `sealed`라 4종을 빠짐없이 다루도록 컴파일러가 강제한다. `ShareCardBuilder.fromRun`도 추가(문서에 "UI가 준비되면 붙인다"고 남겨 두신 그 자리).
- `markAchievementsSeen(Ref, ...)`은 위젯에서 못 부른다(Riverpod 2.x의 `Ref`와 `WidgetRef`는 공통 상위 타입이 없다). 동작 본체를 `_markSeen`으로 두고 `markAchievementsSeenFrom(WidgetRef, ...)`을 얹었다 — 두 경로가 갈라질 여지는 없다.
- `nextAchievementProvider`는 **현재 소비자가 없다.** "한 번에 하나"는 구현했지만, 로컬에서 이미 확인한 건을 제외해야 해서(§2.4) 큐 필터링이 위젯 쪽으로 내려왔다. 계약은 그대로 두었으니 필요 없다고 판단되면 정리해도 된다.

### backend-engineer
- P1 `user_badges.achieved_value`가 생기면 PB 카드의 "기록" 타일이 항상 채워진다. 지금은 102% 초과 구간에서 타일이 통째로 빠지도록 그려 뒀다(레이아웃은 무너지지 않는다).

### gamification-designer
- `Badge.description`이 뱃지 카드의 `subhead`로 **그대로 인스타에 올라간다.** 카드에서 최대 3줄로 잘리므로, 획득 조건 설명체("오전 6시 이전에 10번 달렸어요")가 자랑 문구로 읽히는지 한 번 볼 가치가 있다.

### qa-integration-tester
검증 포인트: (a) 요약 화면 `pending → confirmed` 승격이 실기기 온라인에서 실제로 일어나는지, (b) 캡처 결과가 기기 무관 1080×1920인지, (c) 메달 SVG가 캡처에 실제로 찍히는지(프리캐시 효과 — 시뮬레이터 검증 필요), (d) 밀린 뱃지 20건 상태에서 첫 실행이 다이얼로그 폭탄이 아닌 한 장으로 접히는지.
